## Corrected spec

Base: `https://<proxy>` (operator-defined). Auth header: `Authorization: Bearer sk-...` or `x-litellm-api-key: Bearer sk-...` (default names; the operator may rename the main header).

### A. User holding only a virtual key (user-bound, internal_user role)

1. Budget window: `GET /key/info` with no params (uses the auth key).
   Response: `{ "key": "...", "info": { "key_alias", "spend", "max_budget", "budget_duration", "budget_reset_at", "status", "models", "tpm_limit", "rpm_limit", "expires", "last_active", "model_max_budget_usage?", "budget_limits_usage?" } }`.
   `spend` is the current budget window's spend. `budget_reset_at` is the ISO datetime when the window ends and spend goes to 0.
2. Daily, weekly and monthly spend (needs `user_id`): first get `info.user_id` from `/key/info`, then call
   `GET /user/daily/activity/aggregated?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD&user_id=<own>&timezone=<getTimezoneOffset()>&include_current_utc_day=true`.
   Use one call over the last 31 days, then compute day, week and month sums client-side from `results[]`.
   Response: `{ "results": [ { "date": "YYYY-MM-DD", "metrics": { "spend", "prompt_tokens", "completion_tokens", "total_tokens", "api_requests", "successful_requests", "failed_requests", "cache_read_input_tokens", "cache_creation_input_tokens", ... }, "breakdown": { "models": {name: {metrics, metadata}}, "providers": {...}, "api_keys": {...}, "endpoints": {...}, ... } } ], "metadata": { "total_spend", "total_prompt_tokens", "total_completion_tokens", "total_tokens", "total_api_requests", "page", "total_pages", "has_more", ... } }`.
   A missing or other `user_id` gives 403 or an implicit own-user scope. Service-account keys (user_id null) get 403.
   Day = UTC bucket. `timezone` only extends the end to today's UTC bucket (opt-in), and does not shift historical days.
3. Fallback for a key with no user_id: `GET /spend/logs?api_key=<sha256 or sk->&start_date=YYYY-MM-DD&end_date=YYYY-MM-DD` (summarize=true by default). It returns `[ { "startTime": "YYYY-MM-DD", "spend": n, "users": {}, "models": {} } ]`. It is deprecated and capped at 10,000 rows. The admin-flavoured `api_key` filter is not checked against ownership in the code I read, so it is unverified whether a non-admin may pass another key. Prefer `/key/info` for a single number.

### B. Admin with the master key

- `GET /user/daily/activity/aggregated?start_date=&end_date=` with no `user_id` returns global per-day spend across all users. Add `user_id=` to filter. The same response shape as above.
- `GET /team/daily/activity` and `GET /tag/daily/activity?tags=a,b` for team and tag scopes (paginated, `page_size` default 10 for tags).
- `GET /global/spend/report?start_date=&end_date=&group_by=team|customer|api_key` for grouped reports.
- `GET /global/spend/logs` (last 30 days, admin-only, hidden from the schema). Avoid; the daily activity endpoints are better.
- Admin-view-only role can also read the /user/daily/activity family.

All date params are `YYYY-MM-DD`, inclusive, UTC-bucketed. No enterprise licence is required on any of these handlers as read. A DB-backed proxy is required.
