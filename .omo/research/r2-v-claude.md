## Corrected spec

Read only. Never call the redeem endpoint.

1. `GET https://claude.ai/api/organizations` -> array; choose org whose `capabilities` contains `chat`; id = `uuid`.
2. `GET https://claude.ai/api/organizations/{uuid}/usage?cedar_ember=1&skip_spend=1`
   - Headers: `Accept: application/json` (+ `credentials:'include'`; the `sessionKey` cookie is sent by the browser). No anthropic-client-* header is used by claude-monitor or CodexBar.
   - `skip_spend=1` is used by Desktop/CLI; CodexBar web sends only `cedar_ember=1`. Either works in shipping tools; omit `skip_spend` if you want the `extra_usage` data.
   - Retry once without `cedar_ember` when status is not 200/401/429 and the 403 is not a Cloudflare challenge (challenge = HTML "Just a moment...", `Cf-Mitigated: challenge`).
3. Response (shape, values illustrative; grant sub-object is taken from a real inspection):
```json
{
  "five_hour": {"utilization": 37.0, "resets_at": "<ISO-8601 or null>"},
  "seven_day": {"utilization": 12.0, "resets_at": "<ISO-8601 or null>"},
  "seven_day_opus": null, "seven_day_sonnet": null,
  "extra_usage": {"is_enabled": true, "monthly_limit": 10000, "used_credits": 10197, "currency": "USD"},
  "limits": [{"kind":"session|weekly_all|weekly_scoped","percent":37.0,"resets_at":"...","scope":{"model":{"display_name":"..."}}}],
  "cedar_ember": {
    "eligible": true,
    "ineligible_reason": null,
    "grants": [{"id":"opus55-launch-promax-20260921","resets_left":1,"starts_at":"2026-09-22T16:00:00+00:00","ends_at":"2026-10-22T16:00:00+00:00","paused":false,"usable_now":true}]
  }
}
```
Meanings: `utilization`/`percent` = percent used (number); `resets_at` = end of window (null if not started); `extra_usage` money in cents; `cedar_ember` is null/absent without the flag; `eligible:false` means no inventory (not zero resets on the OAuth route); a grant counts when `!paused && resets_left>0 && starts_at<=now<ends_at` (null bounds open); total available = sum of `resets_left`; next expiry = min `ends_at`.
4. Immediate grant detection: poll the above (<=60 s floor). Fire the alert when the available count rises, or a new `id` appears, or a previously seen id's `resets_left` increases. A count drop with a matching window reset means a grant was spent. Keep ids only in `chrome.storage.session`/local, never log them (they are redemption handles).
5. Fallback detection: Statuspage feed from r1 (unchanged, still unverified for reset text) and the local utilization-drop heuristic.
