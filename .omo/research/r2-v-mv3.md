## Corrected spec
Session-based fetch (Claude), from the service worker only:
- Manifest: `manifest_version: 3`, `permissions: ["storage","alarms"]`, `optional_permissions: ["notifications"]`, `host_permissions`: `https://claude.ai/api/organizations`, `https://claude.ai/api/organizations/*/usage` (add `/prepaid/credits`, `/overage_spend_limit` only if shown).
- Request: `GET https://claude.ai/api/organizations` to discover org id(s); then `GET https://claude.ai/api/organizations/{orgId}/usage`. Options: `credentials: 'include'`, header `Accept: application/json, text/plain, */*`. No Origin/Referer spoofing, no DNR.
- Errors: 401/403 = "signed out of claude.ai" state; other non-2xx = transient; keep last snapshot with `fetchedAt`.
- Response: claude-monitor's `mapApiUsageToStoredShape` reads `usage.limits` (array) and `usage.extra_usage`; field-level meanings (5 h and 7 d percent, reset timestamps) were NOT captured in this pass (see Still unverified).
- Schedule: `chrome.alarms.create(name, {periodInMinutes: 5})` is proven in production; minimum allowed is 0.5. Alarm handler refetches, writes snapshot to `storage.local` (10 MB quota), keeps nothing secret.

Session-based fetch (ChatGPT): `GET https://chatgpt.com/api/auth/session` with `credentials:'include'`, `host_permissions: ["https://chatgpt.com/*"]` (production repo uses `https://chatgpt.com/`). This returns the session JSON (accessToken, user), not the usage meter; the usage endpoint is not verified here.

Platform limits: SW idle 30 s, alarms min 30 s (period 0.5 min), `permissions.request` only inside a user gesture, storage.session 10 MB in-memory, hidden from content scripts unless `setAccessLevel`.
